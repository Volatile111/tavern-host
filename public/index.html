Panel settings

Remote access

Lets people use the panel from other devices (another system, a phone, or over the internet with port forwarding). Uses HTTPS so passwords and API keys are encrypted. This system and the desktop app always work, even when it is off.

Windows will ask for admin permission. Needed once so other devices can connect.

The certificate is created by the panel, so browsers show a "not secure / not private" warning the first time. That is expected: continue to the site. Only accounts with "Remote login" ticked can log in remotely.

Nodes (other systems)

Manage servers on other systems from this panel. On the other system, open Tavern Host → Settings → Use this system as a node, copy the code, and paste it here. Their servers then show in the list on the left, grouped by system. If that system also runs Tavern Vault in node mode, its Storage shows there too (no extra code needed). A system with only Tavern Vault (no Tavern Host) can be added too: Tavern Vault → Settings → Node mode makes its own code (thvault://…) to paste here.

Storage (Tavern Vault)

This needs Tavern Vault, a separate app, on each system that has the drives, with its Node mode turned on (Tavern Vault → Settings → Node mode). A system gets a Storage entry in the list on the left only when Tavern Vault is connected there; systems without it show nothing.

Turn this on here to see storage, and also in Tavern Host on each node whose storage you want to see from here. Nodes need no new code: storage comes through the same node link as their servers (Nodes, above). Tavern Vault doesn't need to be on this panel's own system.

Use this system as a node

Lets a Tavern Host on another system (e.g. your main system) manage this system's servers. Needs Remote access on (above). The code holds a key that can run this system's servers and, if Tavern Vault is in node mode here, see and manage its storage (but not manage users or settings): treat it like a password, and don't paste it into chats.

Backup copies

Also copy every backup to another drive, a NAS or a network share (e.g. A:\Tavern Host Backups), so worlds survive if this system's disk fails. Each server gets its own folder there. Copies older than the limit are removed, but the newest 3 per server always stay.

Integrations

Nexus Mods (Valheim): with your personal API key, Valheim servers can install mods from Nexus Mods. Get it at nexusmods.com → Site preferences → API keys ("Personal API key"). It's checked with Nexus Mods and stored only on this system.

API reference

Send the key in a header with every request: Authorization: Bearer th_… (or X-Api-Key: th_…). Keys made before the Tavern Host rename start with gsp_ and still work. Use http://127.0.0.1:8190 on this system, or the remote address (https://…) from elsewhere. Bodies are JSON (Content-Type: application/json). Each request needs the permission shown, on that server (or all servers) for the key; the owner can do everything.

Examples:
curl -H "Authorization: Bearer th_…" http://127.0.0.1:8190/api/servers
curl -X POST -H "Authorization: Bearer th_…" -H "Content-Type: application/json" -d "{\"command\":\"say hi\"}" http://127.0.0.1:8190/api/servers/{id}/command
Live updates: GET /api/events is a Server-Sent Events stream (server, line and removed events) for everything the key can see.
